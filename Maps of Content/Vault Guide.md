# The Perfect Obsidian Vault Structure for Computer Science Students

## Overview
This vault structure is designed to optimize:
- Knowledge retention
- Concept linking
- Long-term usability
- Low friction workflows

---

## Folder Structure

```
/Inbox
/Notes
  /Concepts
  /Algorithms
  /Data Structures
  /Systems
  /Mathematics
  /Programming
  /Projects
/MOCs
/Templates
/Attachments (optional)
```

---

## /Inbox — Capture Layer

### Purpose
Temporary storage for unprocessed information.

### Contains
- Raw lecture notes
- Quick ideas
- Questions
- Copy-pasted snippets

### Rules
- No structure required
- Must be processed within 24–72 hours

---

## /Notes — Knowledge Layer

### Purpose
Permanent, atomic knowledge.

### Principles
- One concept per note
- Self-contained
- Written in your own words
- Heavily linked

---

### Subfolders

#### /Concepts
Abstract ideas:
- Recursion
- Dynamic Programming
- Concurrency

#### /Algorithms
Procedures:
- Binary Search
- Dijkstra
- Merge Sort

#### /Data Structures
Structures:
- Hash Table
- Heap
- Graph

#### /Systems
Low-level topics:
- Virtual Memory
- Scheduling
- Synchronization

#### /Mathematics
Foundations:
- Big-O
- Probability
- Linear Algebra

#### /Programming
Language-specific:
- Python idioms
- C pointers
- Java streams

#### /Projects
Applied knowledge:
- Link to concepts used
- Document decisions

---

## /MOCs — Maps of Content

### Purpose
Navigation layer for your knowledge graph.

### Characteristics
- Link-heavy
- Minimal explanations
- Organized by topic

### Example
```
# Algorithms

## Searching
- [[Binary Search]]

## Sorting
- [[Merge Sort]]
```

---

## /Templates — Standardization

### Purpose
Reusable note structures.

### Example Templates

#### Concept
```
# {{title}}

## Definition
## Explanation
## Example
## Related
```

#### Algorithm
```
# {{title}}

## Idea
## Steps
## Complexity
## Code
```

#### Lecture
```
# {{date}}

## Topics
## Notes
## Questions
## To Process
```

---

## /Attachments (Optional)

### Purpose
Store non-markdown assets:
- Images
- PDFs
- Diagrams

---

## Workflow

1. Capture → /Inbox
2. Process → /Notes
3. Organize → /MOCs
4. Standardize → /Templates

---

## Key Principles

- Organize by meaning, not courses
- Prefer linking over folders
- Keep notes atomic
- Use MOCs as entry points
- Build a knowledge graph, not a notebook

---

## Mental Model

- Notes = database entries
- MOCs = navigation layer
- Vault = knowledge graph

---

## Final Advice

Your vault should scale beyond university.

Build it as:
> A lifelong system for understanding computer science
